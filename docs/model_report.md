# Power SNMP Anomaly Detection — Model Report

**Branch:** `feature-power-snmp-detection`  
**Date:** 2026-05-07  
**Author:** Zuhaib Asgher

---

## 1. Purpose

This pipeline detects anomalies in power infrastructure equipment — UPS, PDU, network PSUs, and environmental sensors — by consuming SNMP telemetry. It combines three detection mechanisms (LSTM autoencoders, Isolation Forest, and a physical rule) with a battery remaining-useful-life (RUL) regression model. The pipeline runs both in batch mode (CSV replay) and in real-time (Kafka streaming).

---

## 2. System Architecture

```
Raw SNMP telemetry (CSV or Kafka topic: snmp-power-events)
         │
         ▼
  power_features.py          ← feature engineering, normalization, sequencing
         │
  ┌──────┴──────────────┐
  │  Baseline LSTM AE   │    ← 18 aggregated health metrics
  │  Phase LSTM AE      │    ← 29 metrics (superset: adds per-phase L1/L2/L3)
  │  Isolation Forest   │    ← point-anomaly detector, per-category feature masks
  │  Overload rule      │    ← output_load_pct > 100 (physics violation)
  └──────┬──────────────┘
         │
  dual_model_scorer.py       ← OR/AND policy, window collapsing, RUL join
         │
  anomaly_results.csv        (all windows)
  anomaly_windows_detail.json (collapsed events, top features, attribution)
  kafka_live_results.jsonl   (streaming)
```

Device categories supported: **UPS**, **PDU**, **network PSU**, **environmental sensor**  
Vendors covered in training data: APC, Eaton, Liebert, Raritan, Cisco, Generic

## 3. Training Pipeline

### 3.1 Synthetic Data Generation

Training data is generated by `data/dataset_builder.py` across 30 device profiles representing the realistic parameter space:

| Category | Capacity range | Voltage | Phase config |
|---|---|---|---|
| UPS | 1–15 kW | 120 V / 230 V | single-phase and three-phase |
| PDU | 1.4–14.4 kW | 120 V / 230 V | single-phase and three-phase |
| Network PSU | 150–200 W | 120 V | single-phase |
| Env sensor | 5 W | 120 V | single-phase |

Each device generates 2,000 rows of SNMP readings. Normal baselines incorporate:
- Circadian load patterns (day/night variation).
- Physics-based battery degradation tied to `install_age_days`.
- Per-phase voltage jitter within ±2 V of nominal.

**Anomaly events** are injected additively onto normal baselines (not by overwriting them) for these fault types:

| Fault type | Mechanism | Affected metrics |
|---|---|---|
| `overload` | output_load_pct ramped to 110–120% | load, current, frequency |
| `thermal_runaway` | temperature rises 5–15°C over 10–20 rows | temperature, battery charge |
| `battery_drain` | battery_charge_pct drops 15–40% over event | charge, runtime, current |
| `phase_sag` | one phase voltage drops 10–30 V | per-phase voltages, imbalance |
| `psu_failure` | output_voltage_dev_pct spikes ±20% | output voltage deviation |

Events are pre-generated as non-overlapping intervals so no two fault types overlap on the same device.

### 3.2 Feature Engineering (`preprocessing/power_features.py`)

Feature engineering happens in a fixed order that must be preserved:

1. **Phase aggregation** — `input_voltage_v` recomputed as mean of L1/L2/L3 when per-phase columns are present.

2. **Vendor-agnostic normalization (B2)** — absolute vendor-specific values replaced with device-neutral ratios using registration constants stored in the dataset:

   | Raw feature | Normalized form |
   |---|---|
   | `battery_voltage_v` | `battery_voltage_ratio = v / rated_battery_v` |
   | `battery_current_a` | `battery_current_ratio = a / (capacity / rated_battery_v)` |
   | `input_voltage_v` | `input_voltage_dev_pct = (v − nominal) / nominal × 100` |
   | `output_voltage_v` | `output_voltage_dev_pct = (v − nominal) / nominal × 100` |
   | `output_current_a` | `output_current_ratio = a / (capacity_w / nominal_v)` |

3. **Log compression** — `runtime_remaining_min` receives `log1p` transform to reduce right skew before any delta computation.

4. **Delta features** — per-device rate-of-change computed on log-scaled values (not raw):

   | Delta feature | Source | Notes |
   |---|---|---|
   | `runtime_delta` | `log1p(runtime_remaining_min)` | signed |
   | `battery_charge_delta` | `battery_charge_pct` | signed |
   | `temperature_delta` | `internal_temperature_c` | signed |
   | `output_load_delta` | `output_load_pct` | signed |
   | `phase_L1_voltage_drop`, `L2`, `L3` | per-phase voltages | **negative only** — positive excursions zeroed out |

5. **RobustScaler** — fit on training split only; applied to both baseline and phase feature sets separately. Scaler artifacts saved alongside model weights.

### 3.3 Train/Test Split

Time-based split — no shuffling anywhere in the pipeline. For each device independently:
- **Training**: first 85% of rows (chronological).
- **Test**: last 15% of rows.

LSTM training uses only normal (non-anomaly) rows so that reconstruction error on anomalous sequences exceeds the threshold.

### 3.4 Baseline LSTM Autoencoder

**Architecture:**

```
Encoder:  LSTM(input=18, hidden=64, layers=1) → Linear(64 → 32)
Decoder:  LSTM(input=32, hidden=64, layers=1) → Linear(64 → 18)
Sequence length: 20 timesteps (sliding window, stride 1)
```

**Training:**
- Adam optimizer, lr=1e-3, batch_size=64, epochs=100.
- MSE loss on reconstruction.
- `output_frequency_hz` excluded from MSE for PDU, network, and env device categories — grid noise creates false positives for these; UPS devices retain it.

**Threshold:**
- Per device-category threshold = 99.9th percentile of per-window reconstruction errors on the training set.
- Not mean+kσ: the error distribution is heavy-tailed and mean+kσ would set thresholds too low.
- Stored in `baseline_metadata.json` keyed by category name.

### 3.5 Phase LSTM Autoencoder

Same architecture as baseline but trained on 29 features (baseline 18 + 14 per-phase L1/L2/L3 metrics + 3 voltage-drop delta features).

**Key differences:**
- Learning rate 0.1× baseline (lr=1e-4) — phase metrics have higher variance; slower learning stabilizes convergence.
- Gradient clipping at `max_norm=1.0` applied every batch.
- Imbalance features clipped to `[0, _IMBALANCE_CLIP_MAX]` before scaling.
- Threshold from validation reconstruction errors (not training), because phase signals are noisier.

**Imbalance features added:**
- `voltage_imbalance_pct` = (max − min of L1/L2/L3) / mean × 100
- `current_skew_pct` = std of L1/L2/L3 currents / mean × 100
- Per-phase `voltage_drop_delta` (L1/L2/L3) — negative-only rate of change

### 3.6 Battery RUL Regression

**Architecture:**

```
LSTM(input=7, hidden=32, layers=2, dropout=0.1) → Linear(32 → 1)
Sequence length: 24 timesteps
```

**Features (7):** `battery_charge_pct`, `battery_voltage_ratio`, `internal_temperature_c`, `runtime_remaining_min`, `battery_current_ratio`, `install_age_days`, `battery_charge_delta`

**Label normalization:** RUL days scaled to `[0, 1]` during training using the dataset maximum. Inference output multiplied by the stored scale factor to recover days. This prevents gradient explosion from large raw-day values.

**Uncertainty:** MC Dropout — model kept in `train()` mode at inference time, 50 forward passes per window. Output = mean ± 1.96 × std (95% CI). This provides calibrated confidence intervals without retraining an ensemble.

**Per-device split:** 70/15/15 per device (not global) so every device contributes to train, val, and test. This was a critical bug fixed in F4/F7 — global split caused devices with late install dates to appear only in test, producing nonsensical 978-day MAE (reduced to 35 days after fix).

### 3.7 Isolation Forest

One IF model per device category, trained on the full feature set for that category. Features masked per category to exclude irrelevant columns (e.g., phase features excluded from env/network masks).

**Integration:**
- IF scores every incoming row immediately upon arrival — no sequence buffer required.
- Minimum score ratio guard: IF flag only raised if `|score| / threshold_score ≥ 1.05`. This suppresses borderline flags near the decision boundary.
- Batch pre-scoring runs on all training rows at initialization to warm the scorer.

## 4. Inference

### 4.1 Dual-Model Scorer (Batch CSV)

`inference/dual_model_scorer.py` processes the full dataset in one pass:

1. Loads both LSTM models, both scalers, IF models, and RUL model.
2. Builds per-device sliding windows of length 20.
3. For each window: runs baseline LSTM, phase LSTM, IF (on every row in window), and overload rule.
4. Applies alert policy (OR or AND) across baseline + phase flags.
5. Final flag = policy flag OR overload rule flag OR IF flag.
6. Outputs:
   - `anomaly_results.csv` — one row per window with all scores and flags.
   - `anomaly_windows_detail.json` — collapsed events (overlapping flagged windows merged), with top-3 anomalous features and peak error timestep per event.

### 4.2 Streaming Processor (Kafka)

`inference/power_stream_processor.py` handles real-time events:

- Maintains a per-device rolling buffer (deque of length 20).
- Applies identical preprocessing transforms as training (B2 normalization, log1p, deltas).
- IF scores each row as it arrives (no buffer needed).
- LSTM scores once the buffer fills to `seq_len`.

**B1 Online Calibration (Welford algorithm):**  
Per-device running mean and variance of reconstruction errors are updated after each scored window. Dynamic threshold = `μ + 3σ`. Cold-start suppression: online threshold not activated until 50 windows have been scored. Before that, the static trained threshold applies. Per-device stats are persisted to disk so calibration survives process restarts.

**E7 Two-Stage Alert Lifecycle:**  
Prevents alert floods during cold-start or device reconnects.

```
SUSPECTED  →  2 consecutive flagged windows  →  CONFIRMED
SUSPECTED  →  1 unflagged window             →  CLEARED
CONFIRMED  →  unflagged window               →  CLEARED
CLEARED    →  flagged window                 →  SUSPECTED
```

The Kafka consumer prints `[EARLY WARNING]` for SUSPECTED state and `[ALERT]` for CONFIRMED. Cleared windows are routed as FP feedback. LSTM-only flags (no IF or overload) get state `LSTM_ONLY`.

## 5. Edge Cases Fixed and Covered

### 5.1 230 V False Positives (B2 — vendor-agnostic normalization)

**Problem:** Early versions trained on 120 V APC devices. When Liebert (230 V) or Eaton (230 V) devices were scored, their raw voltage readings (≈230) were orders of magnitude larger than the scaler's expected range (≈120). This caused near-100% flagging on these devices even in normal operation.

**Fix:** All absolute voltage, current, and power features replaced with ratios and percentage deviations computed against per-device registration constants (`rated_battery_v`, `nominal_voltage_v`, `rated_capacity_w`). A 230 V device and a 120 V device now produce values in the same normalized range.

**Result:** APC and Liebert devices that were producing 100% false positive rates now differentiate normal vs. anomalous operation.

### 5.2 Phase Sag Recall (B3 — voltage drop delta features)

**Problem:** Phase sag events (a phase voltage drops 10–30 V) were being missed by the baseline model because the aggregate `input_voltage_v` (mean of L1/L2/L3) barely moved when only one phase sagged.

**Fix:** Three new delta features added — `phase_L1_voltage_drop`, `phase_L2_voltage_drop`, `phase_L3_voltage_drop` — computed as the per-timestep change in each phase voltage, zeroed on positive excursions (only drops are informative). These are included in the phase model's feature set.

**Result:** Phase sag recall improved from 25% to 100% on the synthetic test set.

### 5.3 Frequency MSE False Positives (F-series)

**Problem:** `output_frequency_hz` fluctuates due to grid noise in PDU, network, and env devices. Including it in MSE caused these device categories to exceed their thresholds during normal operation.

**Fix:** `output_frequency_hz` is excluded from MSE computation for PDU, network, and env categories. UPS devices retain it — frequency deviation is a genuine UPS anomaly indicator (generator switchover, inverter fault).

**Trade-off accepted:** Minor reduction in F1 for true frequency-related events on non-UPS devices.

### 5.4 RUL Label Corruption (F4/F7)

**Problem 1 (F4):** RUL labels were computed globally across all devices, then split. Devices with high install ages ended up exclusively in the test set (temporal clustering). Model never saw aged batteries in training, resulting in 978-day MAE on test.

**Fix:** Per-device 70/15/15 split — each device contributes rows to all three splits independently.

**Problem 2 (F7):** RUL label normalization divided by a scalar that could be zero for devices with no future-replacement label.

**Fix:** Safe division with a floor of 1 day on the normalization denominator. Validation MAE dropped from 978 days to 35 days.

### 5.5 Temporal Data Leakage (F2/F3)

**Problem:** The preprocessing step applied `RobustScaler.fit_transform()` on the entire dataset before splitting. Test set statistics leaked into the scaler, artificially improving eval metrics.

**Fix:** Scaler fitted on training rows only, then `.transform()` applied separately to val/test rows. Applied consistently in both CSV and streaming paths.

### 5.6 MC Dropout Confidence Intervals (F8)

**Problem:** MC Dropout was being run with the model in `eval()` mode, disabling dropout and causing all 50 samples to be identical. CI width was always 0.

**Fix:** Model explicitly set to `model.train()` during MC Dropout inference passes. CI now reflects genuine epistemic uncertainty.

### 5.7 Cold-Start False Positives (B1, E7)

**Problem:** On system start or after a device reconnects, the rolling window buffer is empty. The first windows scored contain initial transients, causing false alerts.

**Fix (B1):** Per-device online calibration starts with the static trained threshold, then gradually adapts over 50 windows using a Welford running estimate.

**Fix (E7):** Two-stage alert lifecycle (SUSPECTED → CONFIRMED) requires two consecutive flagged windows before emitting a real alert, absorbing single-window transients.

### 5.8 Point Anomalies Missed by LSTM (E1–E6, Isolation Forest)

**Problem:** LSTM autoencoders are sequence models — a sudden single-row spike gets averaged across the 20-timestep window and may fall below threshold.

**Fix:** Isolation Forest added as a parallel point-anomaly detector. It scores each incoming row immediately without waiting for the buffer to fill. Final alert = LSTM flag OR IF flag OR overload rule. IF uses per-category feature masks to avoid noise from irrelevant features.

### 5.9 Overload Rule (Physics Constraint)

`output_load_pct > 100` is physically impossible during normal operation. An explicit rule flags any such reading independently of the models, providing a zero-latency detector for the overload fault type that does not depend on learned thresholds.

### 5.10 Capability Registry (F10)

**Problem:** Streaming processor was applying phase model to single-phase devices (PDU, env, some UPS), generating spurious imbalance scores.

**Fix:** Per-device capability registry keyed by (category, phase_count) controls which models are activated. Phase model only runs on `phase_count ≥ 3`. RUL model only runs on `category == "ups"`. IF model runs on all categories.

## 6. Evaluation Results (Synthetic Dataset)

Evaluation on 2,019 scored windows across 22 devices, alert policy = **OR**.

### 6.1 Global Summary

| Metric | Value |
|---|---|
| Total windows scored | 2,019 |
| True anomaly windows | 147 |
| True anomaly events (collapsed) | 4 |
| Flagged by baseline LSTM | 863 |
| Flagged by phase LSTM | 96 |
| Flagged by overload rule | 29 |
| Flagged by Isolation Forest | 2 |
| Combined final flags | 863 |

### 6.2 By Category

| Category | Windows | Flagged | True anomaly windows | Precision | Recall |
|---|---|---|---|---|---|
| env | 97 | 0 | 0 | — | — |
| network | 194 | 0 | 0 | — | — |
| pdu | 384 | 23 | 23 | 100% | 100% |
| ups | 1,344 | 840 | 124 | 14.8% | ~100% |

PDU detection is perfect — Raritan PDU (`pdu_7k2_230v`) flagged exactly the 23 anomalous windows. UPS recall is high but precision is low, reflecting the known issue with several Liebert/Eaton/APC devices producing false positives (see Section 7).

### 6.3 By Vendor

| Vendor | Flagged | True anomaly windows | Precision |
|---|---|---|---|
| Raritan | 23 | 23 | 100% |
| Eaton | 189 | 38 | 20% |
| Liebert | 470 | 72 | 15% |
| APC | 181 | 0 | 0% |
| Cisco | 0 | 0 | — |
| Generic | 0 | 14 | — |

**APC false positives** are the most pressing open issue. Two APC devices (`ups_3kw_120v_c`, `ups_5kw_120v_a`) produce 86 and 94 false flags with 0 true anomaly windows. Root cause: reconstruction error distribution for these specific device profiles still exceeds the 99.9th percentile threshold on normal data — likely because their feature variance is higher than the category average used to set the threshold.

**Generic UPS missed detections** (`ups_1kw_120v_b`): 14 true anomaly windows with 0 flags. These are small 1 kW, 120 V devices whose anomaly amplitudes are below the current threshold.
