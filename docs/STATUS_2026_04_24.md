## What We Accomplished Today

### 1. Defined Canonical Features for Power / UPS / Battery MIBs

The biggest milestone today was agreeing on *what* the models will actually learn from.
We extracted and named three clean feature sets that cover the full range of power device data:

- **Baseline UPS Features (14 features)** — the core health signals every UPS exposes:
  battery charge %, voltage, current, temperature, runtime remaining, on-battery status,
  replace flag, input voltage/frequency, output voltage/current/load/frequency/power.

- **Phase-Level Features (25 features)** — extends baseline with per-phase measurements
  for three-phase UPS units: L1/L2/L3 input voltage and current, L1/L2/L3 output current,
  plus derived voltage imbalance % and current skew %.

- **Battery RUL Features (7 features)** — a focused subset for forecasting how many days
  the battery has left: charge %, voltage, current, temperature, runtime remaining,
  charge rate, and approximate discharge cycles.

These are now defined as constants in [config.py](../snmp_anomaly_detection/config.py) so
every stage of the pipeline (preprocessing, training, inference) pulls from the same source
of truth.

### 2. Vendor OID Mapping

Real SNMP devices don't send clean column names — they send raw OID names that differ by
vendor. We built a translation layer in [vendor_oid_map.py](../snmp_anomaly_detection/data/vendor_oid_map.py)
that maps vendor-specific OID names to our canonical feature names:

| Vendor / Standard | Devices Covered |
|---|---|
| APC PowerNet-MIB | SUA, SMT, SRT series UPS |
| Liebert LIEBERT-GP-POWER-MIB | GXT series (single + three-phase) |
| RFC 1628 UPS-MIB | Any standard-compliant UPS |
| Raritan PX2-MIB | PDU devices |
| Generic ENTITY-MIB | Network gear and environmental sensors |

This means the training pipeline is fully decoupled from vendor OID changes — swap a device,
update one dict, nothing else breaks.

### 3. Updated Config for the Power Preprocessing Pipeline

Three new config dataclasses were added to [config.py](../snmp_anomaly_detection/config.py):

- **`PowerDeviceConfig`** — describes a device: category (ups/pdu/network/env), vendor,
  phase count (1 or 3), rated capacity in watts, battery Ah, and expected battery life.

- **`PowerTrainingConfig`** — training hyperparameters tuned for power data: 30 epochs,
  3× std threshold (power signals have wider normal variance), 0.1 dropout for MC Dropout
  confidence intervals on RUL predictions.

- **`PowerInferenceConfig`** — runtime alert policy ("or" = any model triggers an alert,
  "and" = both must agree), RUL urgency thresholds (14-day urgent / 30-day warn),
  and compound alert window (10 minutes).

Project output paths were also extended to separate baseline, phase-level, battery RUL,
and dual-model results into their own directories.

### 5. Battery RUL Model (Architecture Ready)

Built the LSTM regression architecture in [models/battery_rul.py](../snmp_anomaly_detection/models/battery_rul.py):

- LSTM encoder (sequence → hidden state)
- MC Dropout at inference time → produces a confidence interval on the RUL estimate
- Linear head → predicted days to battery replacement
- Advisory thresholds: **Urgent < 14 days**, **Warn < 30 days**

The model is ready to train — it needs the power dataset and a training loop call.

### 6. Power Stream Processor (Inference Wiring)

Wrote [inference/power_stream_processor.py](../snmp_anomaly_detection/inference/power_stream_processor.py)
to handle real-time event routing:

- UPS devices → routed through both the baseline LSTM and the phase-level LSTM (dual model)
- PDU / network / env devices → baseline model only
- **Compound alert**: if a UPS anomaly and a PDU anomaly occur within the same 10-minute
  window, a `COMPOUND_ALERT` is emitted — this catches coordinated power failures early.

---

### 7. Dual Model Scorer (Alert Logic)

[inference/dual_model_scorer.py](../snmp_anomaly_detection/inference/dual_model_scorer.py)
combines scores from both LSTM models using the configured alert policy and writes
structured results to the power_dual output directory.
